# 성능

Lighthouse 13.6으로 로컬 프로덕션 빌드(`pnpm build && pnpm preview`)를 측정했습니다. Chrome을 소프트웨어 WebGL(SwiftShader)로 띄웠기 때문에, GPU가 셰이더 컴파일과 텍스처 업로드를 맡는 실제 기기보다 TBT가 크게 나옵니다. 실행마다 성능 점수가 ±5점 정도 흔들립니다.

소프트웨어 WebGL에서는 첫 화면 직후 메인 스레드가 GPU 작업을 기다리는 일이 무작위로 생기고, 같은 기계에서 다른 작업이 돌면 그 대기가 몇 배로 길어집니다(모바일 시뮬레이션에서는 다시 4배로 계산). 그래서 0.7.1부터는 두 빌드를 한 번씩 번갈아 4쌍을 재고 중앙값을 적습니다.

| 항목                    | 0.1.0 모바일    | 0.2.0 모바일    | 0.1.0 데스크톱  | 0.2.0 데스크톱  |
| ----------------------- | --------------- | --------------- | --------------- | --------------- |
| 성능                    | 58              | 70              | 71              | 72~80           |
| 접근성 · 권장사항 · SEO | 100 · 100 · 100 | 100 · 100 · 100 | 100 · 100 · 100 | 100 · 100 · 100 |
| LCP                     | 3.9초           | 1.1초           | 0.3초           | 0.3초           |
| TBT                     | 2.9초           | 2.6초           | 0.9초           | 0.4~0.8초       |
| CLS                     | 0               | 0               | 0               | 0               |
| 전송량                  | 3.5MB           | 1.9MB           | 3.5MB           | 1.9MB           |

## 개선한 것

| 변경                                                        | 효과                                                     |
| ----------------------------------------------------------- | -------------------------------------------------------- |
| 색·불빛·구름 텍스처를 WebP로, 고도 텍스처를 무손실 WebP로   | 텍스처 3.1MB → 1.5MB (고도 값은 픽셀 단위로 같음을 확인) |
| 육지 고도 격자 Int16 → Uint8                                | 256KB → 128KB                                            |
| 조작 안내 문구를 3D 묶음 밖(사전 렌더링)으로 옮김           | 모바일 LCP가 3D 로딩을 기다리지 않음 (3.9초 → 1.1초)     |
| `ImageBitmapLoader`로 텍스처 해석을 메인 스레드 밖에서      | 첫 화면 긴 작업 감소                                     |
| `compileAsync`로 셰이더를 병렬로 미리 컴파일한 뒤 지구 표시 | 컴파일 중 메인 스레드 멈춤 감소                          |
| 별 5,000 → 3,000개, 픽셀 밀도 상한 2 → 1.75                 | 그리기 부담 감소                                         |

three.js 묶음(약 970KB, gzip 약 270KB)은 `lazy` + `ClientOnly`로 페이지 HTML이 그려진 뒤에 받습니다.

## 0.7.0

> **바로잡음 (0.7.1):** 아래 표는 같은 기계에서 다른 작업이 돌던 때 0.6.3과 0.7.0을 차례로 잰 값이라, 0.7.0 쪽 모바일 TBT·LCP가 GPU 대기로 크게 잡혔습니다. 번갈아 다시 잰 결과(0.7.1 절)로는 모바일도 크게 좋아졌습니다(성능 67.5 → 97, TBT 6.8초 → 0.02초).

0.6.3과 같은 조건(로컬 프로덕션 빌드, Lighthouse 13.6, 소프트웨어 WebGL, 기기마다 3회 중앙값)에서 비교했습니다.

| 항목                    | 0.6.3 모바일    | 0.7.0 모바일    | 0.6.3 데스크톱  | 0.7.0 데스크톱  |
| ----------------------- | --------------- | --------------- | --------------- | --------------- |
| 성능                    | 68              | 66              | 66              | 78              |
| LCP                     | 0.8초           | 2.6초           | 0.2초           | 0.6초           |
| TBT                     | 5.4초           | 5.2초           | 2.1초           | 0.5초           |
| Speed Index             | 4.3초           | 3.5초           | 2.1초           | 1.0초           |
| 첫 화면 전송량          | 467KB           | 277KB           | 467KB           | 277KB           |
| 접근성 · 권장사항 · SEO | 100 · 100 · 100 | 100 · 100 · 100 | 100 · 100 · 100 | 100 · 100 · 100 |

| 변경                                                                                                                | 효과                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3D 첫 화면과 같은 시점의 정지 이미지(WebP 24·62KB)를 사전 렌더링하고, three.js 묶음은 첫 상호작용이나 5초 뒤에 받음 | 첫 화면에서 3D 초기화(셰이더 컴파일 등)가 빠져 데스크톱 TBT 2.1초 → 0.5초, 첫 화면 전송량 467KB → 277KB                                                                                                                                                              |
| 패널·조작 막대의 배경 흐림(`backdrop-filter`) 제거                                                                  | 트레이스에서 첫 화면 직후 메인 스레드가 컴포지터를 기다리고, 그동안 GPU 프로세스가 흐림을 그리던 시간이 약 0.9초 → 30ms(데스크톱 크기, SwiftShader, 3회). 이 대기는 흐림 없이도 가끔 생깁니다(0.7.1 절). 실제 기기에서도 매 프레임 바뀌는 3D 위의 흐림 계산이 없어짐 |

모바일 LCP가 늘어난 것은 LCP 요소가 제목 글자에서 정지 이미지로 바뀌었기 때문입니다. 첫 화면 직후 메인 스레드는 컴포지터를 기다리고, 그동안 소프트웨어 GPU가 첫 화면을 그립니다. 이 대기는 실측 약 0.3초인데 모바일 시뮬레이션은 CPU 4배 감속으로 계산하고, 이미지 표시가 그 뒤로 밀립니다. 모바일 TBT도 대부분 이 대기입니다. GPU(Apple M1 Max, Metal)로 띄우면 같은 페이지의 첫 화면 최장 작업은 모바일 화면 크기에서도 약 30ms입니다.

3D 초기화는 이제 상호작용 뒤에 일어나 Lighthouse 측정 범위 밖입니다. 같은 GPU 기기에서 첫 상호작용부터 3D 지구가 보이고 정지 이미지가 사라지기까지 약 1.4초 걸렸습니다(묶음 0.04초, 텍스처 0.5초 포함). 소프트웨어 WebGL에서는 셰이더 컴파일 때문에 약 10초 걸립니다.

## 0.7.1

같은 기계에서 두 빌드를 한 번씩 번갈아 4쌍을 쟀습니다(Lighthouse 13.6, 소프트웨어 WebGL, 중앙값).

| 항목           | 0.6.3 모바일 | 0.7.1 모바일 | 0.6.3 데스크톱 | 0.7.1 데스크톱 |
| -------------- | ------------ | ------------ | -------------- | -------------- |
| 성능           | 67.5         | 97           | 75.5           | 95             |
| TBT            | 6.8초        | 0.02초       | 0.57초         | 0.13초         |
| LCP            | 0.8초        | 2.6초        | 0.2초          | 0.6초          |
| Speed Index    | 4.4초        | 1.6초        | 1.3초          | 0.8초          |
| 첫 화면 전송량 | 467KB        | 253KB        | 467KB          | 281KB          |

- 0.6.3의 TBT는 대부분 첫 화면의 3D 초기화(셰이더 컴파일 등)입니다. 0.7.0부터는 이 일이 상호작용이나 5초 뒤로 옮겨져 측정 범위 밖입니다.
- LCP가 늘어난 것은 LCP 요소가 제목 글자에서 정지 이미지로 바뀌었기 때문입니다(0.7.0 절의 설명).
- 0.7.0과 0.7.1을 같은 방식으로 비교하면 성능(모바일 97 · 91, 데스크톱 87 · 90.5)과 LCP(모바일 2.6초, 데스크톱 0.6초)에 의미 있는 차이가 없습니다. 큰 TBT가 나온 회차는 두 빌드 모두 무작위로 생긴 첫 화면 GPU 대기였습니다. 미리 받기 자체는 모바일에서 약 90ms(시뮬레이션) 작업 하나로 보입니다.

| 변경                                                                          | 효과                                                                                                                                                                        |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 페이지를 다 받고 1초 뒤 한가할 때 3D 묶음을 불러 두고 텍스처를 미리 받아 해석 | 첫 상호작용 뒤 3D가 보이기까지 약 1.4초 → 0.8초(Apple M1 Max, 로컬 서버). 처음에는 하이드레이션 직후 바로 받았는데, 첫 화면 그리기와 겹쳐 모바일 LCP가 약 0.2초 늦어져 미룸 |
| 페이지가 준비되기 전의 첫 입력을 인라인 스크립트로 기록                       | 준비되자마자 3D를 그림(전에는 다음 입력이나 5초 대기)                                                                                                                       |
| 정지 이미지 800px 추가                                                        | 화면 밀도 2배 미만 모바일은 62KB 대신 34KB. 측정 점수에는 차이가 없었음                                                                                                     |
